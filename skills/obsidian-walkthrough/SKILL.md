# Obsidian 逐站精读 / 逻辑点讲解

将一份密集技术内容（论文 / 算法 / 系统设计 / 复杂概念）拆成**多文件 + Obsidian 内链**的渐进式学习材料。结合"按逻辑点拆分讲解、用户确认后再推进"的节奏。

## 触发场景

- 用户在 Obsidian vault 下说"我想精读 X 论文"、"带我读懂 X"、"拆解一下 X"
- 用户表达"我想搞清楚原理"、"按逻辑点讲给我"
- 用户给出一份 PDF / 长文档要求学习消化

## 核心原则

1. **一站一文件**：每个独立的逻辑模块单独 .md，主文件做索引和路线
2. **概念外置**：阅读路径上遇到的术语、子问题拆成 `概念/` 子目录下独立笔记，正文用 `[[...]]` 内链跳转
3. **节奏感**：输出一站 → 等用户"理解了，继续" → 下一站；遇"还是没理解"换类比重写当前站，**不前进**
4. **不破坏主线**：把细节、定义、对比拆出去，主线保持"输入→矛盾→旧办法为何失败→新办法的位置"的纯净叙事
5. **Obsidian 兼容**：公式行内 `$...$`、行间 `$$...$$`；不用 `>` 引大段（用 `---` 分割）；不用 ```math``` 块

## 目录结构（标准模板）

```
<主题名>/
├── 00_导读.md                ← 入口：一句话目标 / 维度拆解 / 输入输出 / 用户视角 / 与既有工作位置 / 阅读路线
├── 01_<第一站标题>.md        ← 问题是什么 / 为什么需要它
├── 02_<第二站标题>.md        ← 核心概念 / 理论基础
├── 03_<第三站标题>.md        ← 主算法 / 主结构骨架
├── 04_<第四站标题>.md        ← 细节实现
├── 05_<第五站标题>.md        ← 实验 / 局限 / 延伸
└── 概念/
    ├── <术语 A>.md
    ├── <术语 B>.md
    └── <子问题 X>.md
```

站数不固定，3~6 站皆可，按逻辑闭环切。

## 工作流

### 1. 信息收集与对齐
- 询问 / 确认主题范围、用户已有背景、希望深入到哪一层
- 若有 PDF/原文，先 `WebFetch` 或 `Read` 摘要主结构（章节标题 + 各章一句话）
- **暂不写入文件**

### 2. 提交"阅读路线"由用户审阅
输出一段文本（不写盘）：
```
我准备这样拆：
- 00_导读：...
- 01_X：...
- 02_Y：...
- ...
- 概念笔记预计：A、B、C、...
你看路线 OK 吗？要调整哪一站？
```
等用户确认后再动笔。

### 3. 先写 00_导读，停下来等确认
按下方"00_导读 模板"写好后输出，问用户："导读这样可以吗？"
不要顺手把 01 也写了。

### 4. 一站一确认
每写完一站文件：
- 提示用户："已写入 [[N1_xxx]]，请打开看看，理解后说'继续'我开 N+1 站"
- 用户说"还是没理解"或"这块再细一点"→ 换类比、加图示、补反例**重写当前站**，不前进
- 用户对某个术语提问 → 在 `概念/` 下新建笔记并在正文加 `[[...]]` 链接，再继续

### 5. 概念笔记按需创建
- 主线文档遇到第一次出现的术语，立即在 `概念/` 下建立笔记
- 即便当前站不细讲，也先建空骨架（定义 + 一行直觉 + TODO）便于后续补
- 概念之间互链（"参见 [[X]]"、"对比 [[Y]]"）

### 6. 全部完成后回到 00_导读
- 把阅读路线里的 ⬜ 改 ✅
- 末尾补"延伸阅读"或"未覆盖的局限"

## 关键约定（必守）

### 链接语法
- 站间跳转：`[[01_问题是什么]]` 或 `[[01_问题是什么|自定义显示文本]]`
- 跨目录：`[[概念/Allgather 定义]]`
- 概念笔记返指主线：`[[../01_问题是什么]]`

### 公式
- 行内：`$T \geq \frac{m}{B^+(S)}$`
- 行间：`$$ ... $$` 单独成段
- **绝不用** `\(...\)` / `\[...\]` / ```math``` 块

### 排版
- 章节用 `##`、子节用 `###`，不要超过 4 级
- 关键对比一律用表格而非散文
- 用 `---` 分割大段，不用 `>` 引大段
- 输入输出规范用 ```text``` 代码块（不是引用块）

### 命名
- 主题名用中文（如 `ForestColl_读论文`、`Diffusion 精读`）
- 站点文件名带数字前缀：`01_问题是什么.md`、`02_理论下界.md`
- 概念笔记直接用术语名：`Allgather 定义.md`、`Throughput Bottleneck Cut.md`

## 节奏控制（必守）

- **每次输出只推进一站**。哪怕用户没明说"等等"，也要在写完一站后停下来确认
- **看到"理解了/继续"才推进**；模糊回应（"嗯""好"）再问一遍
- **看到"还是没理解"立即换路径**：加类比、加图示、加反例、重写当前站；不要前进
- 用户对术语提问 → 立即建概念笔记并在正文插 `[[...]]`，再回到主线

## 不要做的事

- 不要一次写完全部站点扔给用户
- 不要在主线文档里展开所有定义（拆到 `概念/`）
- 不要用 `>` 引大段原文，会破坏 Obsidian 渲染
- 不要在终端直接渲染数学公式（终端不渲染，写到 .md 让用户在 Obsidian 看）
- 不要在站点里塞实现代码（代码留给项目目录，文档只放伪代码或思路）
